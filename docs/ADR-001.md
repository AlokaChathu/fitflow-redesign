# ADR-001: FitFlow Technology Architecture

**Status:** Accepted

## Context

FitFlow requires Android and iOS applications, web accessibility, AI-based workout personalization,
computer-vision nutrition functionality, real-time social/community interactions, offline-friendly
functionality, secure handling of user information, scalability, and rapid delivery by a mid-sized team.

## Decision

- Use React Native + TypeScript for the mobile application.
- Use React + TypeScript for the web interface.
- Use Node.js + NestJS as the main backend.
- Use Python + FastAPI as an independently scalable AI microservice.
- Use PostgreSQL for authoritative structured data.
- Use Firebase for selected real-time social functionality.
- Use Firebase Authentication for identity management.
- Use Redis for caching.
- Use protected object storage for user-uploaded media.
- Use TensorFlow Lite / suitable device ML where appropriate.

## Rationale

This architecture provides strong mobile code reuse, rapid development, scalability, real-time
functionality, and straightforward AI integration. PostgreSQL provides relational integrity while
Firebase handles workloads where real-time synchronization is most useful. Separating AI workloads
prevents expensive inference from reducing normal API responsiveness.

## Consequences

The hybrid architecture contains more infrastructure components than a Firebase-only solution.
The team must maintain clear service boundaries and monitor data consistency between PostgreSQL
and Firebase. The additional complexity provides improved separation of concerns, data integrity,
and long-term scalability.
